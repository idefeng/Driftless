# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this is

Driftless (零漂移步频节拍器) — a Local-First, zero-network running cadence metronome. Expo SDK 56 + React Native 0.85 (New Architecture) app using expo-router. The core product promise is *zero cumulative beat drift*: beats are scheduled against the hardware audio clock (sample-accurate look-ahead), never with an accumulating `setInterval`. Product spec lives in `docs/Driftless_PRD_v1.6.md` (Chinese; current content is actually v1.7 — the filename is stale). UI copy, comments, and commit-adjacent docs are largely in Chinese; match that when touching user-facing strings.

## Commands

```bash
pnpm install        # install deps
pnpm start          # start dev server (press i / a for iOS / Android)
pnpm ios            # run on iOS simulator/device
pnpm android        # run on Android simulator/device
pnpm web            # browser preview (Metro web bundler)
pnpm typecheck      # tsc --noEmit
pnpm lint           # alias of typecheck
pnpm test           # runs test:i18n + test:ota (node --test unit tests)
pnpm test:i18n      # region/language detection tests
pnpm test:ota       # OTA service-layer tests
```

**Native modules require a development build — they do not run in Expo Go.** `modules/cadence-audio` and `modules/cadence-live` are custom native modules; in Expo Go, `requireNativeModule` throws and the app falls back to JS-only stand-ins (see Architecture below). To hear real audio or see Live Activities:

```bash
brew install cocoapods        # first iOS run only
pnpm exec expo run:ios         # or: pnpm exec expo run:android
```

`ios/` and `android/` are generated by `expo prebuild` and are gitignored — never hand-edit files under them; edit `modules/*/ios|android`, `app.json`, or `targets/widget` instead and re-run `pnpm exec expo prebuild --clean` if a full regen is needed. Prebuild correctly wires OTA from `app.json`: the regenerated `android/app/src/main/AndroidManifest.xml` carries `expo.modules.updates.ENABLED=true` plus the EAS Update URL (an earlier local manifest had `ENABLED=false` and was fixed by regenerating, not by hand-editing).

## Architecture

### Engine facade (the key abstraction)

`src/state/CadenceContext.tsx` builds an `Engine` facade at runtime, chosen once via `CadenceAudio.isAvailable()`:

- **Native/available** → routes every call (`start`, `stop`, `setBpm`, `setVolume`, `setSound`, `setMix`, `setDucking`) straight to `modules/cadence-audio` (real sample-accurate output: `AVAudioEngine` on iOS, `AudioTrack` on Android, `AudioContext` on Web).
- **Unavailable (Expo Go)** → falls back to `src/audio/CadenceScheduler.ts`, a pure-JS look-ahead scheduler that is a **visual-only stand-in: no sound** (`enqueueBeat` is a no-op stub).

Beat visuals do not depend on engine callbacks: the native `onBeat` polling bridge has been removed, and `BeatBars` self-animates with Reanimated on a per-beat period (`periodMs`, intended as `60000/bpm`).

Any new engine capability must be added to the `Engine` interface and implemented on both branches (native module + JS fallback), or it will silently no-op in Expo Go.

### Native modules (`modules/`)

Two local Expo modules, each with `ios/` (Swift), `android/` (Kotlin, cadence-audio only), and a `src/*.web.ts` implementation, unified behind a `src/index.ts` that resolves the platform build:

- **`cadence-audio`** — the audio engine itself. Look-ahead scheduling window is 100–200ms (PRD §3.1); BPM changes apply at the next beat boundary, never mid-beat ("natural finish, instant re-rate", PRD §3.4). Three click timbres are synthesized programmatically in native code (short, no silence padding, normalized) — not sampled audio files. iOS session uses `.playback + .mixWithOthers` for coexist mode (PRD §3.2) and handles call interruptions; Android routes beats through `USAGE_MEDIA` (media volume stream, so hardware volume keys control the beat volume — a deliberate choice, see the comment in `CadenceAudioModule.kt`): coexist mode requests no audio focus and auto-mixes with music, exclusive mode requests `AUDIOFOCUS_GAIN`, and ducking requests `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`.
- **`cadence-live`** — drives the lock-screen / always-on presentation: iOS Live Activity (via `targets/widget`, a WidgetKit+ActivityKit extension built with `@bacons/apple-targets`) and an Android foreground-service notification. Countdown state (`endTimeMs`) is pushed once and counted down natively — the JS side does not tick it every second. `addActionListener` surfaces lock-screen taps (±1 BPM, skip phase) back into `CadenceContext`.

When editing either module's native side, mirror the change across iOS/Android/Web — the three implementations are meant to be behaviorally identical (see README's "三平台同构实现").

### State (`src/state/CadenceContext.tsx`)

Single `CadenceProvider` at the app root holds all cross-screen state: BPM, play/pause, sound, coexist mode, beat volume, ducking, keep-awake, the structured workout `plan` (array of `PlanPhase`), and live running-session state (phase index, remaining time). Consumed via `useCadence()`. Notable behaviors baked into this file, not obvious from a quick skim:

- App always launches paused — never auto-plays on load (deliberate, see comment in `CadenceProvider`).
- `startWorkout`/`advancePhase` re-rate the engine at phase boundaries and reset `phaseEndRef` (absolute end timestamp), which is what native lock-screen countdowns read from.
- Keep-awake (`expo-keep-awake`) is only held while `keepAwake && isPlaying`, released immediately otherwise.
- Android 13+ requests `POST_NOTIFICATIONS` at startup so the live workout notification can show later.

### Routing (`app/`, expo-router)

One file per screen, flat (no nested route groups): `index` (main metronome), `sounds` (timbre picker), `coexist` (audio coexistence settings), `plan` (structured workout editor), `running` (active workout). Stack config and font loading (Sora for display/numerals, Manrope for body, via `@expo-google-fonts`) happen once in `app/_layout.tsx`, which also wraps everything in `ThemeProvider` → `CadenceProvider`.

### Theme (`src/theme/`)

`tokens.ts` defines the full design-token palette (light/dark) and is the single source of truth for brand color — **one accent only, sunny orange `#FF8C2B`** (`brand.base`), no second high-saturation accent color, per PRD brand rules. Dark mode uses warm charcoal, deliberately never pure black. `ThemeContext` exposes `useTheme()` → `{ c: Palette, isDark }`; components read colors from `c`, never hardcode hex values for anything that should adapt to scheme.

### Components (`src/components/`)

Shared primitives used across screens: `BeatBars` (waveform/pulse visualization), `PlayPauseButton`, `StepButton`/`MiniStepper` (±BPM controls sized for blind/sweaty-finger operation per PRD pain point 3), `Screen` (layout wrapper), `ui.tsx` (chips, icons, misc small pieces), `Logo`.

## Conventions worth knowing before editing

- BPM is clamped to 100–250 via `clampBpm` in `src/audio/CadenceScheduler.ts` — reuse it rather than re-deriving bounds.
- `@/*` path alias maps to `src/*` (see `tsconfig.json`); `strict` TypeScript is on.
- `react-native-worklets/plugin` must stay the **last** entry in `babel.config.js`'s plugins list (Reanimated 4 requirement).
- The app version is maintained in `app.json` (`expo.version`; keep `package.json`'s `version` in sync). Android `versionCode`/`versionName` are **not** set in `app.json` — `eas.json` uses `cli.appVersionSource: "remote"`, so EAS manages app versions remotely and build profiles bump `versionCode` via `autoIncrement`.
